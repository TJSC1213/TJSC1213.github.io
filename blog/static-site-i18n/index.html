用纯 HTML/CSS/JS 做一个中英双语静态博客

2026 年 9 月 12 日 8 分钟阅读
前端 JavaScript 建站

这个站没有用 Jekyll、Hugo 或 Astro，也没有引入任何 CDN。整个仓库就是几个 HTML 文件、一份 CSS 和三个加起来不到 600 行的脚本。这篇记录几个关键决定是怎么做的。

为什么不用框架

框架解决的问题是「内容多、结构重复、手工维护成本高」。而一个人写的博客通常只有几十个页面，重复的部分其实是可控的。相比之下，框架带来的是构建步骤、依赖升级、以及一个需要长期维护的工具链。

还有一个更实际的理由：不依赖 CDN 意味着没有网络请求依赖，页面在任何网络条件下都能完整渲染，也不会因为某个 CDN 域名被墙而变慢。

双语：让 HTML 自己携带翻译

常见做法是准备两份文案（JSON 字典或两套目录），再由脚本填充。这里换了个思路：把两种语言都写在元素上。 

<!-- 中文文本同时作为无 JS 时的默认值 -->
<a href="/" data-zh="首页" data-en="Home">首页</a>

<!-- 属性也能翻译，后缀就是属性名 -->
<button id="menu-toggle"
        data-zh-aria-label="打开导航菜单"
        data-en-aria-label="Open navigation menu">☰</button>

这样做有几个好处：默认值就是 HTML 里写的文本，禁用 JavaScript 时站点依然可读；新增一段文案不需要同时改两个文件；对比翻译时两种语言就在同一行。

切换逻辑本身很短 —— 遍历所有元素，把匹配当前语言后缀的属性值写回去： 

// 属性名形如 data-zh、data-en、data-zh-html、data-zh-aria-label
var ATTR_RE = /^data-(zh|en)(?:-(.+))?$/;

function applyTo(el, lang) {
  for (var i = 0; i < el.attributes.length; i++) {
    var attr = el.attributes[i];
    var m = ATTR_RE.exec(attr.name);
    if (!m || m[1] !== lang) continue;

    if (!m[2]) {
      el.textContent = attr.value;        // data-zh / data-en
    } else if (m[2] === 'html') {
      el.innerHTML = attr.value;          // data-zh-html
    } else {
      el.setAttribute(m[2], attr.value);  // 其它任意属性
    }
  }
}

document.getElementById('lang-toggle').addEventListener('click', function () {
  i18n.set(i18n.lang === 'zh' ? 'en' : 'zh');
});

有个容易踩的坑：不能用 querySelectorAll('[data-zh], [data-en]') 来找元素，因为 data-zh-aria-label 这种形式匹配不到属性选择器。直接遍历所有元素反而更简单也更正确。

主题：在首次绘制之前决定

深浅色主题如果等脚本加载完再切换，用户会看到一闪而过的白屏。解决办法是在 head 里放一段同步脚本，在渲染前就把 data-theme 写到 html 上 —— 这段脚本必须内联，不能 defer。 

:root {
  --bg: #ffffff;
  --text: #17191c;
  --accent: #4f46e5;
}

/* 所有颜色都走变量，切换主题只需要换一组值 */
html[data-theme="dark"] {
  --bg: #0e1014;
  --text: #e7e9ec;
  --accent: #8b8cf8;

  color-scheme: dark;   /* 让滚动条、表单控件也跟着变 */
}

把 color-scheme 一起写上，浏览器原生的滚动条、输入框和下拉菜单也会跟着切换，不用自己写样式。

代码高亮：核心不到六十行

引入 highlight.js 大约是 100KB 的体积和一个额外依赖。实际上博客里常见的语言就那么几种，每种语言的分词规则可以压缩成一个正则 —— 把多条规则合成一个多分支正则，用捕获组的序号反查命中的类型。

关键约束是：规则内部必须全部使用非捕获组，否则分支编号会错位。分词完成后再做 HTML 转义，就不会出现标签注入。

部署到 GitHub Pages

仓库名必须叫 <用户名>.github.io，推上去之后 GitHub 会自动把它发布到根域名。因为是纯静态文件，不需要任何构建步骤，也不需要写 Actions 工作流。 

# 在仓库目录里初始化，然后推到 GitHub
git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin git@github.com:TJSC1213/TJSC1213.github.io.git
git push -u origin main

# 本地预览：直接起一个静态服务器即可
python -m http.server 8000

还有一个容易漏掉的细节：加一个空的 .nojekyll 文件。GitHub Pages 默认会跑一遍 Jekyll，而 Jekyll 会忽略以下划线开头的文件 —— 放上 .nojekyll 可以完全跳过这一步。

小结

  • 内容量不大的个人站，手写比引入构建工具更省心。
  • 把两种语言放在同一个元素上，维护成本比两套文案低得多。
  • 主题切换必须在首次绘制前完成，否则一定闪。
  • 自写高亮的成本比想象中低，而且没有 CDN 依赖。
